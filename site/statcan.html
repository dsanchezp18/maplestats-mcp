{en}Statistics Canada publishes through many separate services: a table API and an SDMX API, a classification service, census APIs and download pages, microdata ZIPs, feeds and catalogues. MapleStats covers {{statcan_family_count}} of them with {{statcan_tool_count}} tools, so an agent can go from a question to a table, a series, a census profile or a weighted estimate from microdata, and cite where each number came from.{fr}Statistique Canada diffuse ses données par de nombreux services distincts : une API de tableaux et une API SDMX, un service de classifications, des API et des pages de téléchargement du recensement, des ZIP de microdonnées, des flux et des catalogues. MapleStats en couvre {{statcan_family_count}} avec {{statcan_tool_count}} outils. Un agent passe ainsi d'une question à un tableau, une série, un profil du recensement ou une estimation pondérée tirée de microdonnées, et cite la source de chaque chiffre.{/}

  • {en}Codebooks in every format StatCan ships.   • {en}The right weight. The survey weight defaults to the codebook's main weight. Names alone mislead: in one file WTQ_05 is a question about night work, in another DOHWT is an inclusion flag, so labels and field widths are checked too.{fr}Le bon poids. Par défaut, le poids d'enquête est le poids principal du dictionnaire. Les noms seuls induisent en erreur : dans un fichier, WTQ_05 porte sur le travail de nuit; dans un autre, DOHWT est un indicateur d'inclusion. Les étiquettes et la largeur des champs sont donc vérifiées aussi.{/}
  • {en}The sample count beside every estimate.   • {en}Standard errors only where the method is documented. Each variance formula is copied from the survey's user guide and checked against it. {en}Why the live services, not mocks. The first StatCan build called only 2 of its 32 tools against the real API; the rest passed tests written against hand-made fixtures. Calling all 32 live found 9 more bugs that the fixtures could not catch, among them wrong field names for 4 of the 10 code-set categories and footnotes that are objects, not strings. The rule since then: before a client is done, a script calls every function it exports against the real API, and the test suite fails for any module without a live smoke test.{fr}Pourquoi les services réels, et non des simulations. La première version du module n'appelait que 2 de ses 32 outils sur l'API réelle; les autres passaient des tests écrits d'après des données fictives. L'appel en direct des 32 outils a révélé 9 autres bogues que ces données ne pouvaient pas détecter, dont des noms de champs erronés pour 4 des 10 catégories d'ensembles de codes et des notes qui sont des objets, pas des chaînes. La règle depuis : avant qu'un client soit terminé, un script appelle chacune de ses fonctions sur l'API réelle, et la suite de tests échoue pour tout module sans test de fumée en direct.{/}
