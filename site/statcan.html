{en}StatCan's data sits behind several services. The Web Data Service (WDS) serves tables and time series as JSON. An SDMX REST API serves the same tables as SDMX-ML. Reference Data as a Service (RDaaS) holds classifications such as NAICS. The 2021 Census Profile has its own SDMX API on another host, the 2016 profile has a separate JSON API, and the profiles from 2001 to 2016 exist as bulk downloads. Public use microdata files (PUMFs) are ZIP archives. Smaller services cover The Daily and its release calendar, the Data catalogue, the survey directory, geography, merchandise trade by commodity, the open databases and the daily bulk-update files.{fr}Les données de Statistique Canada passent par plusieurs services. Le Service de données Web (WDS) sert les tableaux et les séries chronologiques en JSON. Une API REST SDMX sert les mêmes tableaux en SDMX-ML. Le service de données de référence (RDaaS) contient les classifications comme le SCIAN. Le Profil du recensement de 2021 a sa propre API SDMX sur un autre hôte, celui de 2016 une API JSON distincte, et les profils de 2001 à 2016 n'existent qu'en téléchargement en bloc. Les fichiers de microdonnées à grande diffusion (FMGD) sont des archives ZIP. Des services plus petits couvrent Le Quotidien et son calendrier des diffusions, le catalogue Données, le répertoire des enquêtes, la géographie, le commerce de marchandises par produit, les bases de données ouvertes et les fichiers quotidiens de mise à jour en bloc.{/}

MapleStats wraps these services in {{statcan_tool_count}} tools, and the agent does not see them as a list. The server shows a client three tools: plan_query, search_tools and call_tool. The agent finds each StatCan tool with a plain-language query to search_tools and runs it through call_tool. The first request of a StatCan question is therefore not a request to StatCan:{fr}Chaque service a ses identifiants, ses façons d'échouer et son propre format de corps de requête. {en}From a question to a table{fr}D'une question à un tableau{/}

{{count_tables}}

{en}tables were in the WDS inventory on {{cases_captured}}. Every table search reads that list.{fr}tableaux figuraient dans l'inventaire du WDS le {{cases_captured}}. Chaque recherche de tableau lit cette liste.{/}

{en}Every StatCan table has a product ID, the PID. The PID is the table number without its dashes: table 18-10-0004-01 is PID 18100004, because the last two digits, a view of the table, are optional. The server's docs://statcan/addressing resource breaks down the full ten digits: two for the subject, two for the product type, four for the sequence and two for the view.{fr}Chaque tableau de Statistique Canada a un identifiant de produit, le PID. C'est le numéro du tableau sans ses traits d'union : le tableau 18-10-0004-01 a le PID 18100004, puisque les deux derniers chiffres, qui désignent une vue du tableau, sont facultatifs. La ressource docs://statcan/addressing du serveur détaille les dix chiffres : deux pour le sujet, deux pour le type de produit, quatre pour le numéro séquentiel et deux pour la vue.{/}

{en}wds_search_cubes turns words into a PID with a simple method. It downloads getAllCubesListLite, the list of every table in WDS, caches it for an hour and looks for the query as a substring of each English and French title. That is how it finds the consumer price index table.{fr}wds_search_cubes transforme des mots en PID par une méthode simple. Il télécharge getAllCubesListLite, la liste de tous les tableaux du WDS, la garde en cache une heure et cherche la requête comme sous-chaîne de chaque titre, français et anglais. C'est ainsi qu'il trouve le tableau de l'indice des prix à la consommation.{/}

{en}Substring matching has one clear limitation. "consumer price index" finds the CPI tables because their titles contain those words. A question worded differently from StatCan's titles can miss them, and the agent then has to search again in StatCan's terms. The provenance reports how much was searched. Each result carries cansim_id, the table's number in the old CANSIM system, and release_time, the table's latest release.{fr}La correspondance de sous-chaîne a une limite claire. « consumer price index » trouve les tableaux de l'IPC parce que leur titre contient ces mots. Une question formulée autrement que les titres de Statistique Canada peut les manquer, et l'agent doit alors chercher de nouveau avec les termes de Statistique Canada. La provenance indique l'étendue de la recherche. Chaque résultat porte cansim_id, le numéro du tableau dans l'ancien système CANSIM, et release_time, la dernière diffusion du tableau.{/}

{en}Coordinates and vectors{fr}Coordonnées et vecteurs{/}

{en}A StatCan table is a cube. Each dimension has a tree of members, and one member from each dimension identifies one series. wds_get_cube_metadata returns the dimensions. The CPI table has two: Geography, with {{sc_members_geo}} members, and Products and product groups, with {{sc_members_prod}}.{fr}Un tableau de Statistique Canada est un cube. Chaque dimension a un arbre de membres, et un membre de chaque dimension désigne une série. wds_get_cube_metadata renvoie les dimensions. Le tableau de l'IPC en a deux : Géographie, avec {{sc_members_geo}} membres, et Produits et groupes de produits, avec {{sc_members_prod}}.{/}

{{sc_n_series}}

{en}series in the CPI table, out of {{sc_combos}} combinations of its two dimensions.{fr}séries dans le tableau de l'IPC, sur {{sc_combos}} combinaisons de ses deux dimensions.{/}

{en}Member IDs repeat across dimensions: in both, member 2 is the root of the tree, the member with no parent (Canada, and All-items). Not every combination exists. {{sc_members_geo}} geographies times {{sc_members_prod}} products would make {{sc_combos}} series, but the table has {{sc_n_series}}. A coordinate therefore has to name a series StatCan publishes.{fr}Les identifiants de membres se répètent d'une dimension à l'autre : dans les deux, le membre 2 est la racine de l'arbre, celui qui n'a pas de parent (Canada, et Ensemble). Toutes les combinaisons n'existent pas. {{sc_members_geo}} géographies fois {{sc_members_prod}} produits donneraient {{sc_combos}} séries, mais le tableau en compte {{sc_n_series}}. Une coordonnée doit donc désigner une série que Statistique Canada publie.{/}

{en}A coordinate lists one member ID per dimension, in dimension order, separated by dots. WDS always expects exactly ten positions, with zeros for the dimensions a table does not have. The client adds the padding, so a request for {{sc_coord_in}} sends {{sc_coord_out}}. The response is the vector: a stable ID for one series, the "V" number carried over from CANSIM.{fr}Une coordonnée aligne un identifiant de membre par dimension, dans l'ordre des dimensions, séparés par des points. Le WDS exige toujours exactement dix positions, avec des zéros pour les dimensions que le tableau n'a pas. Le client ajoute ces zéros : demander {{sc_coord_in}} envoie {{sc_coord_out}}. La réponse est le vecteur, un identifiant stable pour une série, le numéro « V » hérité de CANSIM.{/}

{en}One rule matters more to me than the others: the server never applies the scalar factor. value is exactly what WDS sent. The code states this twice, in the schema's docstring ("deliberately NOT applied ... WDS never auto-applies it either") and first on the list in docs://statcan/gotchas. A value in thousands stays in thousands, with its code beside it. Scaling takes one line: apply_scalar_factor(value, code) multiplies by ten to the power of the code. I leave that line to whoever uses the number, where it stays visible. The tool returns what WDS returns, digit for digit.{fr}Une règle compte plus que les autres pour moi : le serveur n'applique jamais le facteur scalaire. value est exactement ce que le WDS a envoyé. Une valeur en milliers reste en milliers, avec son code à côté. La mise à l'échelle tient en une ligne : apply_scalar_factor(value, code) multiplie par dix à la puissance du code. Je laisse cette ligne à qui utilise le chiffre, là où elle reste visible. L'outil renvoie ce que le WDS renvoie, chiffre pour chiffre.{/}

{en}Slicing tables with SDMX{fr}Découper un tableau avec SDMX{/}

{en}WDS works in series: give it vectors or coordinates and it returns their observations. Some questions cover a whole slice of a large table, such as every detailed geography or every occupation. Going series by series then means finding every coordinate first, and downloading the full table means taking far more data than the question needs. StatCan's SDMX API does the slicing on the server. A key names the members you want, dimension by dimension, and a blank position is a wildcard.{fr}Le WDS raisonne en séries : donnez-lui des vecteurs ou des coordonnées, il renvoie leurs observations. Certaines questions portent sur toute une tranche d'un grand tableau, comme chaque géographie détaillée ou chaque profession. Procéder série par série oblige alors à trouver d'abord chaque coordonnée, et télécharger le tableau complet revient à prendre bien plus de données que la question n'en demande. L'API SDMX de Statistique Canada fait le découpage côté serveur. Une clé nomme les membres voulus, dimension par dimension, et une position vide sert de joker.{/}

{en}The data request puts the dataflow and the key in the path: {{sc_sdmx_url}}{fr}La requête de données met le flux de données et la clé dans le chemin : {{sc_sdmx_url}}{/}

{en}The key is the coordinate without its padding: one position per non-time dimension. sdmx_get_vector_data builds the key from a vector. It looks up the vector's coordinate through WDS, reads the table's SDMX structure to count its dimensions and cuts the coordinate to that length. v{{sc_vector}} becomes the key {{sc_sdmx_key}}.{fr}La clé est la coordonnée sans ses zéros de remplissage : une position par dimension autre que le temps. sdmx_get_vector_data construit la clé à partir d'un vecteur. Il cherche la coordonnée du vecteur par le WDS, lit la structure SDMX du tableau pour compter ses dimensions et coupe la coordonnée à cette longueur. v{{sc_vector}} devient la clé {{sc_sdmx_key}}.{/}

{{sc_rate}}/s

{en}SDMX lives on the same host as WDS, so the two share one rate limiter, set below the 25 requests a second StatCan documents per IP.{fr}L'API SDMX est sur le même hôte que le WDS : les deux partagent un seul limiteur de débit, réglé sous les 25 requêtes par seconde par adresse IP que Statistique Canada documente.{/}

{en}The client handles three quirks of this API.{fr}Le client tient compte de trois particularités de cette API.{/}

{en}It answers in XML{fr}Elle répond en XML{/}

{en}StatCan's SDMX endpoint returns SDMX-ML for both data and structure, even when a request asks for JSON with format=jsondata or an Accept header. The constants file records this as confirmed live, against benchmark documentation that assumed SDMX-JSON. The client therefore parses the XML itself, with defusedxml rather than the standard library parser.{fr}Le point d'accès SDMX de Statistique Canada renvoie du SDMX-ML, pour les données comme pour la structure, même quand la requête demande du JSON avec format=jsondata ou un en-tête Accept. Le fichier de constantes note que c'est confirmé en direct, à l'encontre d'une documentation de référence qui supposait du SDMX-JSON. Le client lit donc le XML lui-même, avec defusedxml plutôt que l'analyseur de la bibliothèque standard.{/}

{en}Wildcards sample big dimensions{fr}Les jokers échantillonnent les grandes dimensions{/}

{en}If a dimension with more than about 30 codes is left blank, the response holds a sparse, unpredictable sample of its codes, not all of them. sdmx_get_key_for_dimension builds the complete version instead. It reads the dimension's codelist from the structure, keeps the leaf codes (those that are no other code's parent) and joins them with + into an explicit OR key, which goes into the key at that position.{fr}Si une dimension de plus d'une trentaine de codes reste vide, la réponse contient un échantillon clairsemé et imprévisible de ses codes, pas leur totalité. sdmx_get_key_for_dimension construit plutôt la version complète. Il lit la liste de codes de la dimension dans la structure, garde les codes terminaux (ceux qui ne sont parents d'aucun autre) et les joint par des + en une clé OR explicite, à insérer dans la clé à cette position.{/}

{en}One combination is refused{fr}Une combinaison est refusée{/}

{en}lastNObservations together with startPeriod or endPeriod gets HTTP 406. The client rejects that combination before sending anything. If a 406 comes back anyway, the error names the usual cause instead of passing on the bare status.{fr}lastNObservations combiné à startPeriod ou à endPeriod reçoit HTTP 406. Le client refuse cette combinaison avant d'envoyer quoi que ce soit. Si un 406 revient malgré tout, l'erreur nomme la cause habituelle au lieu de transmettre le statut nu.{/}

{en}Microdata, weights and replicates{fr}Microdonnées, poids et répliques{/}

{{count_pumf}}

{en}microdata products in the Data catalogue on {{cases_captured}}, counted by catalogue number across every page of results.{fr}produits de microdonnées dans le catalogue Données le {{cases_captured}}, comptés par numéro au catalogue sur toutes les pages de résultats.{/}

{en}Tables are aggregates. A public use microdata file holds the records themselves, one row per respondent, with weights that scale the sample up to the population. StatCan ships PUMFs as ZIPs, and the codebooks inside come in several formats: CSV codebooks, Stata .dct and .do files, SPSS label files and SAS files.{fr}Les tableaux sont des agrégats. Un fichier de microdonnées à grande diffusion contient les enregistrements eux-mêmes, une ligne par répondant, avec des poids qui ramènent l'échantillon à l'échelle de la population. Statistique Canada distribue les FMGD dans des ZIP, et les dictionnaires qu'ils contiennent prennent plusieurs formes : dictionnaires CSV, fichiers Stata .dct et .do, fichiers d'étiquettes SPSS et fichiers SAS.{/}

{en}~182 MB{fr}~182 Mo{/}

{en}The 2021 Census individuals ZIP, {{sc_pumf_zip}}, downloaded once and cached. Reading its codebook fetches only the ZIP's file list and the codebook itself.{fr}Le ZIP des particuliers du recensement de 2021, {{sc_pumf_zip}}, téléchargé une fois puis mis en cache. Lire son dictionnaire ne récupère que la liste des fichiers du ZIP et le dictionnaire lui-même.{/}

{en}The table APIs do not cover PUMFs. The only place to find them is StatCan's Data catalogue, which statcan_reference_search_data searches. Once the agent has a file, statcan_pumf_get_codebook reads its codebook from inside the ZIP with HTTP range requests, so the variables and weights are known before the data file is downloaded. statcan_pumf_tabulate then computes on the server with DuckDB. Its first call downloads the file into a local cache, and later calls reuse it.{fr}Les API de tableaux ne couvrent pas les FMGD. Le seul endroit où les trouver est le catalogue Données de Statistique Canada, que statcan_reference_search_data interroge. Une fois le fichier trouvé, statcan_pumf_get_codebook lit son dictionnaire à l'intérieur du ZIP par des requêtes HTTP partielles : on connaît les variables et les poids avant de télécharger le fichier de données. statcan_pumf_tabulate fait ensuite les calculs sur le serveur, avec DuckDB. Son premier appel télécharge le fichier dans un cache local, et les appels suivants le réutilisent.{/}

{{sc_pumf_n}}

{en}respondents behind the {{sc_pumf_cells}} cells of this table, standing for {{sc_pumf_weighted}} people once weighted (unweighted_n, weighted_total).{fr}répondants derrière les {{sc_pumf_cells}} cellules de ce tableau, qui représentent {{sc_pumf_weighted}} personnes une fois pondérés (unweighted_n, weighted_total).{/}

{en}Two things determine whether a table like this one is correct. The first is the weight. The tool defaults to the codebook's main weight, {{sc_census_weight}} here. It checks labels and field widths as well as names, because names can mislead: in the CSWC, WTQ_05 is a question about working at night, and in the CCHS, DOHWT is a height-and-weight inclusion flag. Real weights are wide numeric fields, so a known width under four columns rules a variable out. The second is the sample behind each cell. Every cell carries its unweighted count, and by default the tool flags cells with fewer than 30 respondents as low_count.{fr}Deux éléments déterminent la justesse d'un tel tableau. Le premier est le poids. Par défaut, l'outil prend le poids principal du dictionnaire, ici {{sc_census_weight}}. Il vérifie les étiquettes et la largeur des champs en plus des noms, car les noms peuvent tromper : dans la CSWC, WTQ_05 est une question sur le travail de nuit, et dans l'ESCC, DOHWT est un indicateur d'inclusion pour la taille et le poids. Les vrais poids sont des champs numériques larges : une largeur connue de moins de quatre colonnes écarte donc une variable. Le second est l'échantillon derrière chaque cellule. Chaque cellule indique son effectif non pondéré, et par défaut l'outil marque low_count celles de moins de 30 répondants.{/}

÷ {{sc_census_divisor}}

{en}for {{sc_replicates}} replicates: (240/35) × (1/240), the Fay adjustment in the 2021 Census Individuals PUMF User Guide, chapter 3, section C.2.{fr}pour {{sc_replicates}} répliques : (240/35) × (1/240), l'ajustement de Fay du guide de l'utilisateur du FMGD des particuliers du recensement de 2021, chapitre 3, section C.2.{/}

{en}For standard errors, the Census file carries {{sc_replicates}} replicate weights, {{sc_replicate_first}} to {{sc_replicate_last}}. The tool computes the estimate once with the main weight and once with each replicate. It then sums the squared deviations of the {{sc_replicates}} replicate estimates from their mean, divides by {{sc_census_divisor}} and takes the square root. The divisor of {{sc_census_divisor}} comes from the user guide: it is a Fay adjustment over {{sc_replicates}} groups, and the comment above it in tabulate.py shows the arithmetic, (240/35) × (1/240). StatCan notes that this method overestimates the error for small estimates.{fr}Pour les erreurs-types, le fichier du recensement contient {{sc_replicates}} poids de réplication, de {{sc_replicate_first}} à {{sc_replicate_last}}. L'outil calcule l'estimation une fois avec le poids principal et une fois avec chaque réplique. Il additionne ensuite les écarts au carré des {{sc_replicates}} estimations répliquées à leur moyenne, divise par {{sc_census_divisor}} et prend la racine carrée. Le diviseur {{sc_census_divisor}} vient du guide de l'utilisateur : c'est un ajustement de Fay sur {{sc_replicates}} groupes, et le commentaire qui le précède dans tabulate.py en montre le calcul, (240/35) × (1/240). Statistique Canada signale que cette méthode surestime l'erreur des petites estimations.{/}

A file gets a method only after I have read its guide, "never by analogy with another survey", as the comment above the list puts it. {{statcan_variance_count}} files have one so far:{fr}Je reprends chaque méthode du guide de l'utilisateur de l'enquête, en citant la section. Un fichier n'en reçoit une qu'une fois son guide lu, « never by analogy with another survey », selon le commentaire qui précède la liste. {{statcan_variance_count}} fichiers en ont une pour l'instant :{/}

{en}For any other PUMF, the result gives no standard error, says why and names the replicate weights or bootstrap file it found. PUMF bootstrap weights are perturbed for confidentiality, so their standard errors are comparable to StatCan's official ones but not identical. Two demos use the 2021 Census file this way: bachelor's degrees by province and low income across immigrant generations.{fr}Pour tout autre FMGD, le résultat ne donne pas d'erreur-type, explique pourquoi et nomme les poids de réplication ou le fichier bootstrap trouvés. Les poids bootstrap des FMGD sont perturbés pour protéger la confidentialité : leurs erreurs-types sont comparables à celles de Statistique Canada, sans être identiques.
